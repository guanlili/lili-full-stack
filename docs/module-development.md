# 业务模块交付流程

适用于 Codex、Claude Code 及人工开发。Claude Code 的 `/new-feature` 使用同一清单；模板不自动生成未经设计的业务实体。

## 开始前

阅读 `PROJECT_CONTEXT.md`、`CLAUDE.md`、`AI_RULES.md`，检查 `git status` 和现有实现。把需求整理为以下最小规格，能从上下文确定的内容直接复用，只询问影响实现的缺失信息：

| 项目 | 必须说明 |
|------|----------|
| 角色和动作 | 谁能查看、创建、编辑、删除、导入、导出 |
| 数据范围 | 本人、所属组织、全局；管理员例外是否允许 |
| 模型约束 | 必填、唯一性、外键、删除规则、状态流转 |
| 页面交互 | 列表筛选、分页、表单、空状态、加载、错误反馈 |
| 验收场景 | 正常路径、越权、跨用户访问、重复提交及业务边界 |

## 固定交付顺序

1. 定义模型和请求/响应 schema。仅有数据库结构变化时生成并人工检查 Alembic 迁移，检查索引、约束、历史数据兼容性及回滚影响。
2. 实现 CRUD 和 API，并注册路由。按需使用 `CurrentUser` 或 `get_current_active_superuser`；复杂角色权限在项目需要时实现，权限判断不能替代资源所属用户/组织的过滤。事务由同一业务操作统一提交，不让审计辅助函数决定核心业务是否落库。
3. 编写独立 `app_test` API 测试，覆盖未登录 401、无权限 403、用户 A 访问用户 B 的资源、管理员策略、无效输入和状态流转。具有一次性或幂等语义的动作补并发测试。
4. API 契约变化后运行 `cd frontend && npm run generate-client`，检查生成 diff，禁止手写 URL 或编辑生成文件。
5. 在 `frontend/src/hooks/` 封装请求，页面和组件复用 hooks；分页与筛选进入 query key，mutation 后使相关缓存失效。退出或切换用户不能复用上一个用户的缓存。
6. 实现页面与导航，提供加载、空状态、失败重试和操作结果反馈。后台任务完成/失败后停止轮询，导出结果提供可用的下载操作。前端可见性不能替代后端权限。
7. 运行后端 lint/测试、前端 lint/会话测试/build、模板完整性检查；涉及部署或备份脚本时执行对应回归。更新 `PROJECT_CONTEXT.md` 的验收项。

## 交付记录

每个模块的 PR 描述写明：解决的问题、角色与数据范围、数据库迁移及兼容性、API 客户端生成结果、验证命令和未验证项。禁止携带测试账号密码、真实客户数据或生产配置。提交与 PR 按当前用户授权执行。
