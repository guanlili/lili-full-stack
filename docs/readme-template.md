# 项目 README 模板

从本模板创建的新项目，交付前把 `README.md` 改写为项目自己的说明。推荐结构（各节按需删减，**项目信息表必填**）：

```markdown
# <项目名> · <一句话定位>

<两三句话：做什么、给谁用、当前状态（算法/数据版本等）>。

## 📌 项目信息

| 项 | 内容 |
|------|------|
| 甲方对接人 | **<姓名>**（需求提出与验收，需求变更以此为准；可多行） |
| 开发 | <谁> |
| 项目管理账本 | [GitHub Project #<编号>](链接)（issue 是唯一工作真相源） |
| 在线平台 | <http://地址:端口> |

![<平台首页截图>](docs/screenshots/dashboard.png)

## 功能

| <页面/模块> | <核心内容> |

<details>
<summary>界面截图（点击展开）</summary>
...
</details>

## 技术栈

<一行式：Python 3.x · FastAPI · React 19 · PostgreSQL · Docker Compose，或表格>

## 本地开发

<克隆后前置条件 + 启动命令 + 冒烟检查；若项目有「数据不在 git 内」等约定，
写清无数据/有数据两条起步路径>

## 部署

<关键命令与前置条件，细节链接 docs/deployment.md，不重复维护>

## 测试

<与 CI 同口径的真实命令>

## 文档

- <本项目文档索引>

## 版本历史

| 阶段 | 时间 | 里程碑 |
|------|------|--------|
| <阶段叙事，不逐版本列号——当前版本看顶部与部署文档，逐条记录看 Project 账本> |
```

要点（来自已交付项目的实践）：

- **项目信息表是必填项**：对接人多个就多行；记账时「需求人」字段以此为准
- **截图是交付物的一部分**：hero 图 + 主要界面折叠块，版本升级时原地重截
- **命令必须真实可跑**：从 CI workflow 抄，不凭记忆写
- **不手工维护派生数据**：当前版本号、逐条交付记录指向唯一真相源（部署文档 / Project 账本）
