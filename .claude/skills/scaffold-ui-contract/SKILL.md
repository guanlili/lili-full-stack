# Scaffold UI Contract — 脚手架 UI 总控规范

本文件是脚手架级别的 UI 工程契约，优先级高于个人审美偏好。配套参考：
- `.claude/skills/frontend-design/`：Anthropic 官方前端反平庸设计指南（调色板、排版、结构、动效、文案的去模板化原则）。
- `frontend/src/index.css`：唯一的设计令牌（CSS 变量）出口；`frontend/src/components/ui/`：唯一的原子组件层。

## 1. 适用范围与触发时机

- 新建 `routes/` 页面、新增业务组件、调整布局或视觉风格时，先读本文件再写样式。
- 收到参考截图/设计稿做"精装修"时，走第 3 节的看图精装修工作流。
- 重构既有页面时，受第 4 节工程铁律约束，先确认禁区边界再动手。

## 2. 审美底线（未指定风格时也必须达到）

即使需求没有提任何视觉要求，交付物也必须满足以下底线；不允许以"默认模板够用"为由降级。

### 2.1 间距与网格

- 严格遵循 **4px / 8px 间距网格**：margin、padding、gap、组件内边距只取 `4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64`（Tailwind `p-2 / p-3 / p-4 / p-6` 等），禁止出现 `p-[13px]`、`mt-[7px]` 这类游离值；确需特殊值时在令牌层定义变量，不写页面级任意值。
- 页面与卡片的左右内边距、栅格断点对齐同一套容器宽度约定；同屏卡片的间距、对齐基线必须一致。

### 2.2 色彩层级（克制的中性灰 + 单一强调色）

- 中性色只通过语义变量取值：`background / foreground / card / muted / muted-foreground / secondary / accent / border / input / ring`。灰度层级要拉开但不超过 5 档；禁止凭空再造一套灰阶。
- 强调色（primary）一个语义角色只对应一个色相；状态色（destructive / warning / success / info）走各自语义变量，不与 primary 混用。
- 文本对比满足可读标准：正文 ≥ 4.5:1，大字号 ≥ 3:1；暗色模式同步校验，不能只调亮背景不调对比。
- 色彩只承担信息职责（层级、状态、选中、错误），不承担纯装饰职责；装饰性渐变、发光、高饱和色块默认禁用，除非需求明确要求。

### 2.3 字体与排版

- 字体族、字号阶梯、行高、字重、字距一律在 `index.css` 的 `@theme`/`:root` 令牌层定义，组件只引用令牌。
- 一套界面最多两个字体族（正文/展示）；标题与正文通过字号、字重、行高、字距区分，不靠额外颜色或斜体点缀单个词。
- 行宽控制在 80 字符以内；标签、表头、说明文字的字号与字重有明确层级，不使用全大写烫金字眉作为默认装饰（详见 frontend-design 的反模式清单）。

### 2.4 光影、边框与质感

- 阴影分多层且柔和：默认卡片用低不透明度、大模糊的软阴影；悬浮态再叠一层更近、略深的阴影；禁止单层 `shadow-md` 通吃所有层级，也禁止硬黑投影。
- 边框统一走 `border` / `input` 变量；描边粗细默认 1px，靠颜色层级（border、input、ring）区分强弱，不随意改粗细。
- 圆角按层级走令牌：`--radius-sm/md/lg/xl`；同一类组件圆角一致，不要卡片 16px、输入框 4px 这种无层级混用。

### 2.5 交互微动效（完整状态，克制使用）

- 所有可交互元素（按钮、输入框、菜单项、表格行、卡片可点区域）必须具备完整状态：**default / hover / active / focus-visible / disabled**；focus 态用 `ring` 变量画出清晰的键盘焦点圈。
- 动效时长与缓动走统一令牌（如 150ms / 200ms，`ease-out`）；hover 位移、颜色、阴影过渡方向一致。
- 非用户触发的入场动效只保留一个编排化的时刻；禁止每个卡片各自 fade-up。必须尊重 `prefers-reduced-motion`。
- loading、空态、错误态同样是视觉的一部分，不能只做成功路径。

## 3. 看图精装修工作流（参考截图 / 设计稿）

拿到截图后，禁止逐像素照抄粗糙细节，按以下顺序处理：

1. **提取骨架与基调**：先判断布局结构（单列/栅格/侧栏-主区/列表-详情）、信息层级、情绪基调（克制商务 / 轻快 / 高对比等）、主强调色与质感方向，用几句话写清"这张图想表达什么"，而不是抄它的间距。
2. **映射到语义令牌**：把截图里的颜色、圆角、阴影、字号映射回 `index.css` 既有变量或新增令牌；截图里的具体 hex 只作为取值参考，落到令牌层后组件引用变量。截图与脚手架中性体系冲突时，以脚手架可读性和对比度为准。
3. **区分可学与不可学**：可学的是层级关系、留白节奏、信息组织、状态反馈；不可照搬的是截图里粗糙的对齐、模糊阴影、默认系统字体、过期组件样式。
4. **先骨架后皮肤**：先搭结构与栅格，再上视觉令牌；完成后对照第 2 节审美底线自检一遍（间距网格、对比、完整交互态、reduced-motion）。
5. **交付前截图回看**：环境允许时跑起来截图自查；发现"通用 SaaS 卡片套壳"感（同款圆角、同款灰阴影、每张卡渐变描边）就回退到令牌层统一处理。

## 4. FastAPI + Shadcn 工程铁律

### 4.1 颜色与样式纪律

- **严禁在业务组件中硬编码 Hex / oklch / hsl 色值**；颜色只能来自语义变量或 `@theme` 令牌。确需新颜色时，先在 `index.css` 令牌层声明，再在组件中引用。
- 优先复用 `src/components/ui/` 下的原子组件（Button、Card、Input、Table、Badge、Dialog、Select 等）；业务组件只做组合与业务变体，不重复造按钮、输入框、表格。
- 样式以 Tailwind 工具类为主；只有动态值、令牌层无法表达的值才允许 inline style，且必须是计算值而非裸色值。
- 不绕过原子组件直接写裸 `<button>` / `<input>` 原生样式（Radix 无障碍语义与焦点态已封装在 ui 组件内）。

### 4.2 禁止改动的逻辑边界

重构页面时，**严禁修改**以下内容，视觉调整不得牵连：

- TanStack Query / Router 的 queryKey、查询与变更封装、路由定义；
- API Client（`src/client/`，OpenAPI 自动生成，禁止手改；接口变更走 `npm run generate-client`）；
- 表单校验逻辑（react-hook-form + zod schema、resolver 绑定）；
- 权限、401/403 会话处理与错误上报链路。

如视觉改造确实需要调整上述代码，先停下来说明原因，交由对应流程处理，不在 UI 改动里夹带。

### 4.3 令牌与主题

- 亮色/暗色双主题都要在令牌层成对维护；新增令牌同时补 `.dark` 取值。
- 切换风格（如换成另一套品牌色/质感）应只通过替换 CSS 变量完成，不改组件工具类结构。
- 组件库风格基准为 shadcn `new-york`（见 `components.json`），升级 ui 组件时保持该风格一致。

## 5. 交付前 UI 自检清单

- [ ] 间距全部落在 4/8px 网格，无游离任意值。
- [ ] 颜色全部来自语义令牌，组件文件内无硬编码色值。
- [ ] 按钮/输入/可点区域具备 hover、active、focus-visible、disabled 完整状态。
- [ ] 卡片、表格、表单的圆角、边框、阴影层级一致。
- [ ] 亮色与暗色对比均达标，focus 圈在两种主题下可见。
- [ ] 未改动 `src/client/`、TanStack Query 封装、zod 校验与路由定义。
- [ ] 入场动效克制，且尊重 `prefers-reduced-motion`。
- [ ] `npm run lint`、`npm test`、`npm run build` 通过。
