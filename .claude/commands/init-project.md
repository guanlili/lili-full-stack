# 初始化新项目

把刚从模板克隆的仓库初始化为具体项目。**你（AI）负责提问收集信息并完成全部初始化**，用户只需回答问题；禁止把参数清单丢给用户让ta自己拼命令。

## 参数

$ARGUMENTS — 可选，用户已提供的信息（如项目名、对接人），已有信息不再重复问。

## 执行原则

- 一次问清、一次执行：所有问题合并成**一轮**提问（带默认值，用户可回答「都按默认」），不要挤牙膏式多轮追问
- 不确定的信息宁可不传参（走脚本默认），也不要编造
- 初始化脚本只跑一次；跑完后**继续完成**下面的后续待办，不要停在「请手动完成剩余步骤」

## 提问清单（合并为一轮）

| # | 问题 | 必要性 | 默认值 |
|---|------|--------|--------|
| 1 | 项目显示名（如「订单管理系统」） | 必问 | 无——不能默认 |
| 2 | 甲方对接人姓名（需求提出与验收人；可多个） | 外包项目必问 | 内部项目可空 |
| 3 | 生产端口 | 建议问 | 与服务器既有项目错开，未占用即用 |
| 4 | 前端品牌名（登录页左侧大标题） | 可选 | = 项目显示名 |
| 5 | 自助注册 | 可选 | closed（管理员建账号模式） |
| 6 | 部署 slug（同一台服务器多项目时需唯一） | 条件必问 | 从显示名推导；纯中文名会生成摘要串，建议显式指定 |

## 执行步骤

1. **确认前置**：当前目录是刚 Use this template 克隆的新仓库（有 `.env.example`、无 `.env`）；若已初始化过（存在 `.env`），停止并说明。
2. **一轮提问**：按上表合并提问，明确告诉用户「回车/『默认』即采用默认值」。
3. **执行初始化**：
   ```bash
   bash scripts/init-project.sh "<项目显示名>" --slug <slug> --brand "<品牌名>" --port <端口> --registration <open|closed>
   ```
   只传已确认的参数。观察输出中的「剩余待办清单」与本机 devledger 接入结果（装有时会自动建 GitHub Project，记录编号）。
4. **填写 PROJECT_CONTEXT.md**：就业务背景、角色权限、核心数据实体向用户做**一轮**提问（用户可答「先跳过」），把已知信息写入，未知处保留 TODO 标记。
5. **README 项目化**：按 `docs/readme-template.md` 骨架改写 README——「📌 项目信息」表必填（甲方对接人/开发/项目管理账本链接/在线平台），devledger 接入成功则把 Project 链接写进去。
6. **AGENTS.md 补对接人**（对接人非空时）：文末追加一行「本项目甲方对接人：**XX**——记账时甲方来源 issue 的需求人字段填 XX」。
7. **首次启动验证**：`docker compose up --build` 后做冒烟检查（登录进 dashboard、`/docs` 可见），通过后停止服务。
8. **汇报**：项目名/slug/端口/Project 编号、已完成项、剩余人工项（Logo/favicon 替换等）。

## 注意

- `.env` 由脚本生成（600 权限），**永远不要**把密钥打印到会话或提交到 git
- 初始化脚本在已有 `.env` 时会拒绝重跑，属预期保护
- devledger 自动接入失败时提示手动命令即可，不阻塞初始化
